# September 22 firmware re-entry

Current main.c was compiled to an object with installed TI ARM 20.2.7.LTS,
TM4C123GE6PM definitions, Cortex-M4/Thumb and FPv4SPD16 options. Compilation
passed. No full CCS link or MCU flash was performed.

COM5/1 Mbps bench tests observed build 1004 (`0.0.3.236`):

- Empty RAM dump returned zero.
- 256-capacity wrap returned 256 ordered samples and an identical repeat dump.
- Oversized request 999999 was capped at 4094.
- Five-second stream produced 5002 host samples; maximum dump returned 4094
  ordered records, identical on repeat, matching the realtime tail exactly.

The first 255 records of the 256 dump matched the realtime tail exactly, with
one final RAM sample unmatched. This is consistent with an unpaired final sample
at stop; it is not proof of zero realtime loss. Power-cycle, long-duration, and
fault tests remain pending.

Detailed results and datasets are in the adjacent MasterPython repository's
TEST_RESULTS.md and ignored Data/reentry* directories. Host fixes handle malformed
SLCAN input and correct within-frame timestamp spacing to 1 ms. MCU source logic
was unchanged in this session; pre-existing main.c changes were line endings.

Before expanding firmware, review ISR/main-loop buffer concurrency, command
guards during acquisition, GlobalTimer early returns, and acquisition sequence
numbers for realtime data. Keep generated Debug build output out of source
commits; this repository currently tracks it, so .gitignore alone is insufficient.
